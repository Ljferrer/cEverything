## Context — the gap / problem

MOLTEN scores "Made with the body", and the operator fixed hands plus voice as the two body inputs, so a headset wearer must be able to steer the selected agent by speaking, not only by typing on the laptop (user; PIN-8). Hermes exposes `POST /api/audio/transcribe {data_url, mime_type}` backed by the host's `stt.*` config, so no STT key is needed outside the host (verified: `hermes_cli/web_server*.py` at `43b6acbe` via lane `speech-input`, read via plan 1's evidence block). Hermes stays bound to `127.0.0.1:9119` behind `HERMES_DASHBOARD_SESSION_TOKEN`, which only the relay holds, so the transcribe call must be made by the relay, never by the page (verified: `hermes_cli/subcommands/dashboard.py` at `59ee4989`, read via plan 1's evidence block). Meta Quest Browser has never exposed `SpeechRecognition`, so in-browser recognition is not a path on the Quest; a recorded blob sent to the host is (verified: Meta release notes through 2026-10-02; Meta forum thread 116827, read via plan 1's evidence block). Both headsets refuse DOM inside an immersive session, so the recording indicator and any interim text must be in-scene troika text (verified: WebKit has no DOM-overlay IDL; Quest DOM overlay unsupported per community threads, medium confidence, read via plan 1's evidence block). A 2024 forum report of 0-byte `MediaRecorder` blobs inside a visionOS immersive session is unresolved, and this plan's build window starts after the Vision Pro slot has ended, so the Quest 3S is the voice demo device (user, calendar screenshot) [assumed: Quest Browser records non-empty blobs in-session — if wrong: voice is cut from the demo and hands stay the one body input]. Plan 1 lands every seam this plan uses: `bus` events dispatched as `CustomEvent`s with the frame in `detail` — `selectstart {sid}`, `selectend {sid}`, `mode` with `canEdit`, and `error` — `bus.selected`, `net.send(cmd)`, the `VRButton` element (three's `VRButton.createButton(renderer)` appended to `document.body` by `src/features/xr.js`, element id `VRButton`), the client command `{t:'voice', sid, mime, data_url}` accepted by `isClientCommand`, and relay command modules `{name, handle(cmd, ctx)}` with `ctx {relay, sources, commands, emit, ownerOf(sid)}`, where `commands` is the loaded command map keyed by `name`, `emit` broadcasts to every client while a command's resolved frame returns only to the issuer, and `ownerOf(sid)` returns the owning source module, which is writable iff `typeof owner.sendCommand === 'function'` (verified: `docs/plans/2026-10-17-obelisks-1-foundation.md` Task 1 and Task 3 slices; `docs/plans/2026-10-17-obelisks-2-hermes-harness.md` D34). Plan 2's `say` command emits the user slab on `sid` and then awaits `owner.sendCommand('prompt.submit', …)`, so a command that delegates to `say` emits no slab of its own (verified: `docs/plans/2026-10-17-obelisks-2-hermes-harness.md` Task 2 slice).

## Pivotal constraints

- Build window from 3 PM to 5:15 PM; the only headset slot after it is the Quest 3S from 5:30 PM to 6:30 PM, so every in-headset End state is judged on the Quest (user, calendar screenshot).

## Commander's Intent

- **Purpose:** a person in the headset steers the selected agent by voice — hold, speak, release — and sees the words rise as a user slab on that obelisk with the agent's answer streaming under them, making voice the second body input beside hands.
- **Method:** grab the mic at the VRButton click and keep the stream; on a held select over the already selected obelisk run a MediaRecorder and show `● REC`; on release ship the blob as a data URL in plan 1's `voice` command; in the relay, `voice.mjs` transcribes through Hermes's own STT route, logs one line per call, and hands the text to plan 2's `say` command through `ctx.commands` — `say` emits the user slab and submits the prompt, and voice emits no slab of its own; a short press sends nothing; a read-only owner or a missing `say` answers with an error.
- **Mechanism latitude:** the glyph's shape, the data-URL encoding (`FileReader` or `arrayBuffer` plus base64), listening on `bus` or on the controller objects for the gesture, the `Enable mic` button's placement and styling, `fetch` versus `node:http` in the command, the interim-text bonus, and the wording of error texts other than `read-only harness`, `say unavailable`, and the `transcribe failed` prefix are implementer's choice; substituting any of these mechanisms while the End states and binding guardrails hold is not a plan deviation and warrants no issue.
- **Binding guardrails:** the client never holds `HERMES_DASHBOARD_SESSION_TOKEN`, an STT key, or the transcribe route; transcription happens in the relay (PIN-9, PIN-15) · hands plus voice are the two body inputs and voice rides the select gesture with no extra in-session button (PIN-8) · a view-only client sends no `voice` command and the relay refuses one anyway (PIN-23) · only `src/features/voice.js`, `server/commands/voice.mjs`, and `server/commands/voice.test.mjs` change; no plan 1 file is edited and `say.mjs` is not imported (PIN-22) · the owner is found through `ctx.ownerOf(sid)`, writable iff `typeof owner.sendCommand === 'function'`, and the command never branches on harness name (PIN-19) · hold-to-talk arms only on the already selected obelisk, and `voice.mjs` emits no slab — the user slab is plan 2's `say` command's (PIN-60, PIN-65) · while `bus.talking` equals a sid, plan 6's `fork.js` skips a base `select` on that sid; plan 5 sets and clears the flag, plan 6 implements the skip (PIN-76) · the wire shape `{t:'voice', sid, mime, data_url}` is plan 1's and stays unchanged · one WebXR codebase for both headsets (PIN-3).

## Phase 1 — Hold-to-talk (3 PM to 5:15 PM)

### Task 1: Client hold-to-talk feature
- Files: `src/features/voice.js`
- Plan slice: export `install({scene, camera, renderer, bus, net})`. Mic: by default add a capture-phase `click` listener on `document` that, when `event.target.closest('#VRButton')` is non-null (plan 1's `xr.js` appends three's `VRButton.createButton(renderer)` to `document.body`, element id `VRButton`), calls `navigator.mediaDevices.getUserMedia({audio:true})` once and keeps the stream in module state (PIN-62); installing before `xr.js` is fine because the button is never looked up at install time. When `new URLSearchParams(location.search).get('mic') === 'button'`, install no capture-phase listener and instead insert a fixed-position `Enable mic` DOM button beside the VRButton whose click requests the same stream (the `?mic=button` fallback; backstop row 2). State: track `canEdit` from `bus` `mode` events (`event.detail.canEdit`). Arming: on `bus` `selectstart` (`sid = event.detail.sid`), proceed only when `sid === bus.selected`, `canEdit` is true, and no recording is running; if the stream is missing, dispatch `talk {phase:'error', sid}`, `console.log('voice: no mic stream')`, and return; otherwise note the start time, pick the mime with `MediaRecorder.isTypeSupported` (`audio/webm;codecs=opus`, else `audio/mp4`, else the recorder default) (PIN-63), start a `MediaRecorder` collecting `dataavailable` chunks, show a troika `Text` reading `● REC` anchored to the camera 0.4 m ahead and 0.15 m down, start a 300 ms timer that sets `bus.talking = sid`, and dispatch `talk {phase:'start', sid}` (PIN-60, PIN-67, PIN-69, PIN-76). Release: on `bus` `selectend` stop the recorder, cancel the timer, and set `bus.talking = null`; in `onstop` build the blob; if the held time is under 300 ms or the blob is empty, remove the glyph, dispatch `talk {phase:'dropped', sid, ms}`, and send nothing (PIN-61); else read the blob as a data URL, call `net.send({t:'voice', sid, mime, data_url})`, remove the glyph, dispatch `talk {phase:'sent', sid, ms}`, and open an error window. Error window: it runs from that `net.send` until the next `bus` `error` event or a 10 s timeout; an `error` inside the window shows its `detail.text` in the glyph label and dispatches `talk {phase:'error', sid}`; the glyph clears when the 10 s timer fires. Bonus, only when `window.webkitSpeechRecognition` exists: start a recognizer with `interimResults = true` at arming, show interim text in a second troika label under the glyph, stop it at release; failures here are swallowed. The feature never references the token, an STT key, or the transcribe route (PIN-15). Laptop mode has no `selectstart`, so the feature is inert there.
- Done when: None — a browser-only feature over plan 1's tested seams and the browser's `MediaRecorder`; the pre-merge check is an emulator smoke the worker runs in desktop Chrome with iwer (the Immersive Web Emulator runtime) against `npm run dev` and a relay whose `OBELISKS_TRANSCRIBE_URL` points at a stub: a hold over 300 ms shows the `● REC` glyph and relay stdout shows one `voice` line, and a press under 300 ms shows none; End states 5, 6, and 7 are judged at the Quest slot

### Task 2: Relay voice command
- Files: `server/commands/voice.mjs`, `server/commands/voice.test.mjs`
- Plan slice: `voice.mjs` exports `{name: 'voice', handle(cmd, ctx)}`. `handle` resolves `owner = ctx.ownerOf(cmd.sid)`; when `owner` is missing or `typeof owner.sendCommand !== 'function'` it emits `{t:'error', text:'read-only harness'}` through `ctx.emit` and returns that frame without any network call (PIN-66; plan 1 Task 1, plan 2 D34).
