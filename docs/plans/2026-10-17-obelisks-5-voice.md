## Context — the gap / problem

MOLTEN scores "Made with the body", and the operator fixed hands plus voice as the two body inputs, so a headset wearer must be able to steer the selected agent by speaking, not only by typing on the laptop (user; PIN-8). Hermes exposes `POST /api/audio/transcribe {data_url, mime_type}` backed by the host's `stt.*` config, so no STT key is needed outside the host (verified: `hermes_cli/web_server*.py` at `43b6acbe` via lane `speech-input`, read via plan 1's evidence block). Hermes stays bound to `127.0.0.1:9119` behind `HERMES_DASHBOARD_SESSION_TOKEN`, which only the relay holds, so the transcribe call must be made by the relay, never by the page (verified: `hermes_cli/subcommands/dashboard.py` at `59ee4989`, read via plan 1's evidence block). Meta Quest Browser has never exposed `SpeechRecognition`, so in-browser recognition is not a path on the Quest; a recorded blob sent to the host is (verified: Meta release notes through 2026-10-02; Meta forum thread 116827, read via plan 1's evidence block). Both headsets refuse DOM inside an immersive session, so the recording indicator and any interim text must be in-scene troika text (verified: WebKit has no DOM-overlay IDL; Quest DOM overlay unsupported per community threads, medium confidence, read via plan 1's evidence block). A 2024 forum report of 0-byte `MediaRecorder` blobs inside a visionOS immersive session is unresolved, and this plan's build window starts after the Vision Pro slot has ended, so the Quest 3S is the voice demo device (user, calendar screenshot) [assumed: Quest Browser records non-empty blobs in-session — if wrong: voice is cut from the demo and hands stay the one body input]. Plan 1 lands every seam this plan uses: `bus` events `selectstart {sid}` and `selectend {sid}`, `bus.selected`, the `mode` event with `canEdit`, `net.send(cmd)`, the `VRButton` element from `src/features/xr.js`, the client command `{t:'voice', sid, mime, data_url}` accepted by `isClientCommand`, and relay command modules `{name, handle(cmd, ctx)}` with `ctx {relay, sources, emit, ownerOf(sid)}`, where `ownerOf(sid)` returns the owning source module, which exports `start({emit, sendCommand})` and optionally `handle(cmd)` — the one inbound seam a writable source exposes (verified: `plan1-final-for-agents.md` Task 1 and Task 3 slices).

## Pivotal constraints

- Build window from 3 PM to 5:15 PM; the only headset slot after it is the Quest 3S from 5:30 PM to 6:30 PM, so every in-headset End state is judged on the Quest (user, calendar screenshot).
- `HERMES_DASHBOARD_SESSION_TOKEN`, any STT key, and the transcribe route live in the relay process only; plan 1's End state 10 grep over `src/` stays green (PIN-9, PIN-15).
- `getUserMedia` must be requested inside a user gesture before the immersive session starts, because no browser permission UI is reachable in-session; the VRButton click is the last gesture before entry (verified: no DOM in-session, plan 1 Pivotal constraints) [assumed: a mic prompt raised in the same click does not cancel `requestSession` on Quest Browser — if wrong: voice.js inserts its own `Enable mic` DOM button beside the VRButton].
- Hold-to-talk shares the select gesture with plain slab selection (plan 1) and with fork and pipe (plan 6); a press shorter than 300 ms is a select, never a recording.
- This plan edits only `src/features/voice.js`, `server/commands/voice.mjs`, and `server/commands/voice.test.mjs`; it never edits a plan 1 file nor another plan's file, and it does not import plan 2's `say.mjs`, which may not exist when this plan's worker runs (PIN-22).

## New domain terms · Recommended ADRs

Hold-to-talk (press and hold the select gesture on a selected obelisk to record, release to send), `talk` event (the `bus` event `voice.js` dispatches at start, sent, dropped, error), `● REC` glyph (the in-scene recording indicator). ADRs: none.

## Commander's Intent

- **Purpose:** a person in the headset steers the selected agent by voice — hold, speak, release — and sees the words rise as a user slab on that obelisk, making voice the second body input beside hands.
- **Method:** grab the mic at the VRButton click and keep the stream; on a held select over a selected obelisk run a MediaRecorder and show `● REC`; on release ship the blob as a data URL in plan 1's `voice` command; in the relay, `voice.mjs` transcribes through Hermes's own STT route and forwards the text exactly as `say` does — a user slab, then `prompt.submit` on the owner; a short press sends nothing; a read-only owner answers with an error.
- **Mechanism latitude:** the glyph's shape and anchor (controller or camera), the data-URL encoding (`FileReader` or `arrayBuffer` plus base64), listening on `bus` or on the controller objects for the gesture, a capture-phase VRButton listener versus an `Enable mic` button inserted by `voice.js`, `fetch` versus `node:http` in the command, the interim-text bonus, the slab `id` scheme, and the wording of error texts other than `read-only harness` are implementer's choice; substituting any of these mechanisms while the End states and binding guardrails hold is not a plan deviation and warrants no issue.
- **Binding guardrails:** the client never holds `HERMES_DASHBOARD_SESSION_TOKEN`, an STT key, or the transcribe route; transcription happens in the relay (PIN-9, PIN-15) · hands plus voice are the two body inputs and voice rides the select gesture with no extra in-session button (PIN-8) · a view-only client sends no `voice` command and the relay refuses one anyway (PIN-23) · only `src/features/voice.js`, `server/commands/voice.mjs`, and `server/commands/voice.test.mjs` change; no plan 1 file is edited and `say.mjs` is not imported (PIN-22) · the owner is found through `ctx.ownerOf(sid)` and the command never branches on harness name (PIN-19) · the wire shape `{t:'voice', sid, mime, data_url}` is plan 1's and stays unchanged · one WebXR codebase for both headsets (PIN-3).
- **End state:**
  1. `handle({t:'voice', sid, mime, data_url}, ctx)` POSTs JSON `{data_url, mime_type}` with the `X-Hermes-Session-Token` header to the URL in `OBELISKS_TRANSCRIBE_URL`, calls `ctx.commands.say.handle` exactly once with `{t:'say', sid, text}` where `text` equals the reply's `text` (the `say` command, plan 2, emits the user slab) · check: `npm install --no-audit --no-fund >/dev/null && node --test server/commands/voice.test.mjs`.
  2. A `voice` command whose `sid` has no writable owner (`ctx.ownerOf` returns `{}`, a source with no `sendCommand` function) emits `{t:'error', text:'read-only harness'}` and the fake transcribe server receives no request · check: `npm install --no-audit --no-fund >/dev/null && node --test server/commands/voice.test.mjs`.
  3. A non-2xx transcribe reply emits a `{t:'error'}` frame whose text starts with `transcribe failed` and calls `ctx.commands.say.handle` zero times · check: `npm install --no-audit --no-fund >/dev/null && node --test server/commands/voice.test.mjs`.
  4. No client file contains the session token name, an API key name, or the transcribe route · check: `grep -rn "SESSION_TOKEN\|API_KEY\|api/audio/transcribe" src/ ; test $? -eq 1 && echo CLIENT_CLEAN`.
  5. On the Quest 3S: select an obelisk, hold the trigger, say two words, release — a user slab carrying those words rises on that obelisk within five seconds · HARD at audit_sha (observable + judge seat).
  6. On the Quest 3S: a trigger press shorter than 300 ms on a selected obelisk produces no `voice` frame in the relay log · HARD at audit_sha (observable + judge seat).
  7. On the Quest 3S: an in-scene `● REC` glyph is visible while the trigger is held and gone after release · HARD at audit_sha (observable + judge seat).

## Phase 1 — Hold-to-talk (3 PM to 5:15 PM)

### Task 1: Client hold-to-talk feature
- Files: `src/features/voice.js`
- Plan slice: export `install({scene, camera, renderer, bus, net})`. Mic: add a capture-phase `click` listener on `document` that, when `event.target` is the VRButton element plan 1's `xr.js` inserts (`id === 'VRButton'`), calls `navigator.mediaDevices.getUserMedia({audio:true})` once and keeps the stream in module state (PIN-62); installing before `xr.js` is fine because the button is never looked up at install time. State: track `canEdit` from `bus` `mode` events. Arming: on `bus` `selectstart`, if the stream exists, `bus.selected` is set, `canEdit` is true, and no recording is running, capture `sid = bus.selected`, note the start time, pick the mime with `MediaRecorder.isTypeSupported` (`audio/webm;codecs=opus`, else `audio/mp4`, else the recorder default) (PIN-63), start a `MediaRecorder` collecting `dataavailable` chunks, show a troika `Text` reading `● REC` anchored to the camera 0.4 m ahead and 0.15 m down (or to the controller when the event names one), and dispatch `talk {phase:'start', sid}` (PIN-60, PIN-67, PIN-69). Release: on `bus` `selectend` stop the recorder; in `onstop` build the blob; if the held time is under 300 ms or the blob is empty, remove the glyph, dispatch `talk {phase:'dropped', sid, ms}`, and send nothing (PIN-61); else read the blob as a data URL and call `net.send({t:'voice', sid, mime, data_url})`, remove the glyph, and dispatch `talk {phase:'sent', sid, ms}`. On a `bus` `error` event while a send is pending, show its text in the glyph label for two seconds and dispatch `talk {phase:'error', sid}`. Bonus, only when `window.webkitSpeechRecognition` exists: start a recognizer with `interimResults = true` at arming, show interim text in a second troika label under the glyph, stop it at release; failures here are swallowed. The feature never references the token, an STT key, or the transcribe route (PIN-15). Laptop mode has no `selectstart`, so the feature is inert there.
- Done when: None — a browser-only feature over plan 1's tested seams and the browser's `MediaRecorder`; judged by End states 5, 6, and 7 at the Quest slot

- requiresPackaging: false

### Task 2: Relay voice command
- Files: `server/commands/voice.mjs`, `server/commands/voice.test.mjs`
- Plan slice: `voice.mjs` exports `{name: 'voice', handle(cmd, ctx)}`. `handle` resolves `owner = ctx.ownerOf(cmd.sid)`; when `owner` is missing or `typeof owner.sendCommand !== 'function'` it emits `{t:'error', text:'read-only harness'}` through `ctx.emit` and returns that frame without any network call (PIN-66). Otherwise it POSTs JSON `{data_url: cmd.data_url, mime_type: cmd.mime}` with headers `content-type: application/json` and `X-Hermes-Session-Token: process.env.HERMES_DASHBOARD_SESSION_TOKEN ?? ''` to `process.env.OBELISKS_TRANSCRIBE_URL ?? 'http://127.0.0.1:9119/api/audio/transcribe'` using global `fetch` (PIN-64); a non-2xx status or a network error emits `{t:'error', text: 'transcribe failed: <status or message>'}` and returns; an empty or whitespace `text` emits `{t:'error', text:'no speech'}` and returns. With a transcript it delegates the transcript by awaiting `ctx.commands.say.handle({t:'say', sid: cmd.sid, text}, ctx)` — plan 1's command delegation seam (`ctx.commands`), the same frame the relay routes for a typed `say` (PIN-65, PIN-15). `voice.test.mjs` (Node's `node:test` and `node:assert/strict`) starts a `node:http` server on an ephemeral port that records method, URL path, headers, and parsed JSON body and answers from a per-test queue; it sets `OBELISKS_TRANSCRIBE_URL` to that server's `/api/audio/transcribe` and `HERMES_DASHBOARD_SESSION_TOKEN` to `devtoken` before importing `voice.mjs`; `ctx` is `{relay: {}, sources: {}, commands: {say: {name:'say', handle(cmd, ctx) {calls.push(cmd); return {t:'ok'}}}}, emit(frame) {frames.push(frame)}, ownerOf(sid) => owner}`, and the fake writable owner is `{sendCommand(method, params) {rpc.push([method, params])}}` (plan 1's writable-source contract). Test one: the queue answers `200 {"text":"hello"}`; after `handle({t:'voice', sid:'s1', mime:'audio/webm', data_url:'data:audio/webm;base64,AAAA'}, ctx)` the recorded request is a POST to the path with header `x-hermes-session-token` equal to `devtoken` and body `{data_url, mime_type:'audio/webm'}`, `frames` contains one `slab` with `role:'user'`, `sid:'s1'`, `text:'hello'`, and `calls` deep-equals `[{t:'say', sid:'s1', text:'hello'}]` (End state 1). Test two: `ownerOf` returns `{}` (no `handle`); `frames` contains `{t:'error', text:'read-only harness'}` and the fake server recorded no request (End state 2). Test three: the queue answers `500`; `frames` contains an `error` whose text starts with `transcribe failed` and `calls` is empty (End state 3). The server is closed in `after`.

## Notes / conscious deviations

- Task 1 has no test by the done-when law: `voice.js` only wires browser APIs (`getUserMedia`, `MediaRecorder`, `FileReader`) onto plan 1's tested seams, and End states 5, 6, and 7 are judged at the Quest slot. Pure helpers were not split into a separate module because this plan's file family is fixed by the roadmap's contention table.
- `voice.mjs` duplicates the two-step `say` path (user slab, then the `say` frame into the owner's `handle`) instead of importing plan 2's `say.mjs`, because plan 2 runs in parallel and its file may not exist in this plan's worktree; the duplication is a few lines and keeps the plans file-disjoint.
- `voice.mjs` forwards through plan 1's command delegation seam `ctx.commands.say.handle({t:'say', sid, text}, ctx)`, so it mirrors no plan 2 call shape. If plan 2's `say` path already emits the user slab from inside the Hermes source's `handle`, `voice.mjs` drops its own `slab` emit at rebase to avoid a duplicate slab, and the worker moves End state 1's slab assertion onto the fake `say` command, which emits that slab through `ctx.emit`.
- A held pinch that lands on an obelisk base also fires plan 1's `select`, which plan 6's fork listens to; this plan publishes `talk` events so plan 6 can ignore a `select` that follows a hold, but the resolution belongs to plan 6 (see Open decisions). The demo script sidesteps it by talking while pointing at a slab.
- Operator pre-flight for this plan (not a WAR task): confirm `stt.provider` and its key in the Hermes setup chat and run the A3 curl before 3 PM; tell the worker the reply shape and the accepted token header if they differ from `{text}` and `X-Hermes-Session-Token`.
