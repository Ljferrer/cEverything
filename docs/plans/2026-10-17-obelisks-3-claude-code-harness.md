## Context — the gap / problem

Claude Code writes one JSON object per line to `~/.claude/projects/<project-slug>/<sessionId>.jsonl`; every `assistant` line holds exactly one `message.content` block and the lines of one API turn share `message.id`, so a turn with thinking, a tool call, and text is three lines (verified: this session's transcript via `jq` over `.message.content | length`, 2026-10-17 11:50 PDT). `user` lines carry `message.content` as a string or as an array of `text` or `tool_result{tool_use_id, content}` blocks, and a `tool_result` line also carries a top-level `toolUseResult`, which for `Edit` and `Write` holds `filePath` and `structuredPatch[]` hunks with `lines[]` (verified: this session's transcript and a `Write` result in another project under `~/.claude/projects`, 2026-10-17). Twelve line types appear in this transcript: `user`, `assistant`, `system`, and the bookkeeping types `attachment`, `queue-operation`, `custom-title`, `agent-name`, `last-prompt`, `atis-latch`, `bridge-session`, `file-history-snapshot`, `file-history-delta`; `user` lines with `isMeta: true` wrap slash-command markup such as `<command-name>` (verified: `jq -r .type | sort | uniq -c` over this session's transcript, 2026-10-17).

Workflow subagents live at `<sessionId>/subagents/workflows/<wf_id>/agent-<agentId>.jsonl` with `isSidechain: true`, `agentId`, and `sessionId` equal to the parent session, beside `agent-<agentId>.meta.json` `{agentType, description, workflowPhase, spawnDepth}` and a `journal.jsonl` of `launched`/`started`/`result` lines; Agent-tool subagents sit one level up at `<sessionId>/subagents/agent-<agentId>.jsonl` with a meta file that has `agentType`, `description`, `toolUseId`, `spawnDepth` and no `workflowPhase` (verified: `wf_fd46e6c9-839` in this session and a subagent pair in another project, 2026-10-17; this settles plan 1's D20 assumption). A session's custom title is `<sessionId>/custom-title.json` `{customTitle}`, mirrored by a `custom-title` transcript line (verified: this session's directory and two other projects under `~/.claude/projects`, 2026-10-17).

The root holds 240 project directories and 336 main transcripts, of which 2 changed in the last 30 minutes and 5 in the last two hours at 11:50 AM today (verified: `find -mmin` over `~/.claude/projects`, 2026-10-17), so tailing everything would flood a room budgeted for six obelisks (verified: plan 1 A7). Node 24 `fs.watch` with `recursive: true` reports a write to a file created after the watch started inside a new subdirectory on this laptop (verified: probe run today). Community visualizers already tail these files zero-config (verified: agent-flow, claude-village, read via plan 1's evidence block, lane `prior-art`). The first user line of a session can open with pasted-content tags and a slash command rather than prose (verified: this session's first `user` line, 2026-10-17).

## Pivotal constraints

- Only this plan's files change: `server/sources/claude.mjs`, `server/sources/claude.test.mjs`, `fixtures/claude/**`; plan 1's files and `package.json` are frozen, so no new npm dependency — `node:fs`, `node:path`, `node:test` only (user; verified: roadmap ownership table).
- The relay loads the module by directory read and calls `start({emit, sendCommand})` with no flags, so the source's configuration must arrive through its own argv or env reading, never through a relay edit (verified: plan 1 Task 1).
- Every emitted frame is one of plan 1's protocol shapes and passes `isServerEvent`; the client never sees a harness-specific field (verified: plan 1 Task 1; PIN-19).
- Claude Code obelisks are read-only targets: the source exports no `handle`, and plan 2's `pipe` answers `read-only harness` for them (user; verified: plan 1 D6).
- One worker, one task, at most 90 minutes inside the window from 3 PM to 5:15 PM; the Quest slot from 5:30 PM to 6:30 PM is the only headset time after this plan lands (user).
- The demo is shared by QR code to anyone at the venue and the repo is a hackathon submission, so fixtures carry placeholder text only — no real transcript content, paths, or titles (user: present a QR code so anyone can hop in).

## Non-goals / deferred

Writing into Claude Code sessions (`say`, `fork`, `pipe` targets) · hook-based push ingestion · `delta` streaming (a transcript line is a whole block; there is no partial text to stream) · live retitling after a `custom-title` line arrives mid-session · rendering `attachment`, `file-history-*`, or `tool-results/` content · reading `journal.jsonl` for anything beyond fixture fidelity · Hermes, pylons, voice, gestures, and state beacons (plans 2, 4, 5, 6).

## New domain terms · Recommended ADRs

Transcript root (the directory `--claude-root` names), recency window (the minutes `--claude-since` names), tool slab (the role `tool` slab that shares its `id` with its `tool` frame). ADRs: none.

## Commander's Intent

- **Purpose:** every Claude Code session active on the laptop, and every subagent it spawns, stands in the room as an obelisk the moment its transcript changes, with no change to the client or the relay.
- **Method:** one read-only source module that tails the transcript tree with `fs.watch` plus a 1 s poll, reads only appended bytes, maps each JSONL line to plan 1's protocol frames, derives status from file growth, and ships with a faithful placeholder fixture tree that the test runs the real discovery over.
- **Mechanism latitude:** the watcher shape (one recursive watch, per-directory watches, or poll only), the appended-bytes reader (stream or `readSync` at an offset), the partial-line buffer, the title's tag stripping, the argument-head and summary text for tool slabs, the text cap on slab and `args` strings, the backfill depth on first read, the rescan cadence, and whether `journal.jsonl` `result` lines mark an agent `idle` are implementer's choice; substituting any of these mechanisms while the End states and binding guardrails hold is not a plan deviation and warrants no issue.
- **Binding guardrails:** read-only — the module exports no `handle` and never writes under the transcript root (PIN-6) · one source module exporting `start({emit, sendCommand})`, every `session` frame carries `harness:'claude'`, the client is untouched (PIN-19) · only `server/sources/claude.mjs`, `server/sources/claude.test.mjs`, and `fixtures/claude/**` change; no plan 1 file, no `package.json`, no new dependency (PIN-22) · every frame passes `isServerEvent` from `shared/protocol.mjs` · fixtures hold placeholder text and `/tmp/demo` paths only, never real transcript content.
- **End state:**
  1. Over the fixture root, `start` emits exactly one `session` with `kind:'chat'` and `harness:'claude'` and exactly two with `kind:'agent'`, each agent carrying `parent` equal to the chat `sid` and `phase` equal to its meta `workflowPhase` · check: `node --test server/sources/claude.test.mjs`.
  2. The same run emits at least one `slab` with role `thinking`, a `tool {phase:'start', name:'Bash'}` and a `tool {phase:'complete'}` with the same `id`, and every emitted frame passes `isServerEvent` · check: `node --test server/sources/claude.test.mjs`.
  3. An `Edit` `tool_result` yields `tool {phase:'complete', diff}` whose `diff` contains the fixture's `structuredPatch` lines · check: `node --test server/sources/claude.test.mjs`.
  4. A line appended to the copied transcript arrives as a `slab` within 2 s at the default poll interval · check: `node --test server/sources/claude.test.mjs`.
  5. `titleOf` prefers `custom-title.json`, else the first user text with tags stripped and cut to 60 characters · check: `node --test server/sources/claude.test.mjs`.
  6. `statusOf` returns `working` within 5 s of growth, `waiting` when the last message line is an `assistant` turn, `idle` otherwise · check: `node --test server/sources/claude.test.mjs`.
  7. Every bookkeeping line type in PIN-45, every `system` line, and every `isMeta` user line produce no frame · check: `node --test server/sources/claude.test.mjs`.
  8. `server/sources/claude.mjs` exports `start` and no `handle` · check: `node --input-type=module -e "const m=await import('./server/sources/claude.mjs');if(typeof m.start!=='function'||'handle' in m)process.exit(1);console.log('CLAUDE_READ_ONLY_OK')"`.
  9. No fixture file carries a real home path · check: `grep -rln "/Users/" fixtures/claude ; test $? -eq 1 && echo FIXTURE_CLEAN`.
  10. With `node server/relay.mjs --source claude` on the laptop while a Claude Code session and one of its workflows run, the room shows the session's obelisk under its custom title and the workflow's agents standing around it under phase labels · HARD at audit_sha (observable + judge seat).
  11. The default recency window keeps the live room to at most 8 chat obelisks on the operator's laptop at demo time · backstop: row.

## Notes / conscious deviations

- The fixture tree nests under `fixtures/claude/demo-project/main/…` rather than the flat `fixtures/claude/main.jsonl` + `fixtures/claude/subagents/…` the task text lists, so `--claude-root fixtures/claude` exercises the real `<root>/<slug>/<sid>` discovery and doubles as a one-flag demo fallback; every named file is present, one level deeper. - `file-history-delta` and `system` join the skip list because they appear in today's transcript; `summary` stays on the list from the task text although no current transcript here contains it.
