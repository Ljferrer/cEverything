## Context — the gap / problem

Claude Code writes one JSON object per line to `~/.claude/projects/<project-slug>/<sessionId>.jsonl`; every `assistant` line holds exactly one `message.content` block and the lines of one API turn share `message.id`, so a turn with thinking, a tool call, and text is three lines (verified: this session's transcript via `jq` over `.message.content | length`, 2026-10-17 11:50 PDT). `user` lines carry `message.content` as a string or as an array of `text` or `tool_result{tool_use_id, content}` blocks, and a `tool_result` line also carries a top-level `toolUseResult`, which for `Edit` and `Write` holds `filePath` and `structuredPatch[]` hunks with `lines[]` (verified: this session's transcript and a `Write` result in another project under `~/.claude/projects`, 2026-10-17). Twelve line types appear in this transcript: `user`, `assistant`, `system`, and the bookkeeping types `attachment`, `queue-operation`, `custom-title`, `agent-name`, `last-prompt`, `atis-latch`, `bridge-session`, `file-history-snapshot`, `file-history-delta`; `user` lines with `isMeta: true` wrap slash-command markup such as `<command-name>` (verified: `jq -r .type | sort | uniq -c` over this session's transcript, 2026-10-17).

Workflow subagents live at `<sessionId>/subagents/workflows/<wf_id>/agent-<agentId>.jsonl` with `isSidechain: true`, `agentId`, and `sessionId` equal to the parent session, beside `agent-<agentId>.meta.json` `{agentType, description, workflowPhase, spawnDepth}` and a `journal.jsonl` of `launched`/`started`/`result` lines; Agent-tool subagents sit one level up at `<sessionId>/subagents/agent-<agentId>.jsonl` with a meta file that has `agentType`, `description`, `toolUseId`, `spawnDepth` and no `workflowPhase` (verified: `wf_fd46e6c9-839` in this session and a subagent pair in another project, 2026-10-17; this settles plan 1's D20 assumption). A session's custom title is `<sessionId>/custom-title.json` `{customTitle}`, mirrored by a `custom-title` transcript line (verified: this session's directory and two other projects under `~/.claude/projects`, 2026-10-17).

The root holds 240 project directories and 336 main transcripts, of which 2 changed in the last 30 minutes and 5 in the last two hours at 11:50 AM today (verified: `find -mmin` over `~/.claude/projects`, 2026-10-17), so tailing everything would flood a room budgeted for six obelisks (verified: plan 1 A7). Node 24 `fs.watch` with `recursive: true` reports a write to a file created after the watch started inside a new subdirectory on this laptop (verified: probe run today). Community visualizers already tail these files zero-config (verified: agent-flow, claude-village, read via plan 1's evidence block, lane `prior-art`). The first user line of a session can open with pasted-content tags and a slash command rather than prose (verified: this session's first `user` line, 2026-10-17). While a tool call is in flight the last transcript line is the assistant `tool_use` and its `tool_result` has not been written yet, so "last line is an assistant turn" alone would read a long `Bash` or `Workflow` call as waiting for a human (verified: this session's transcript during its own workflow, 2026-10-17).

## Pivotal constraints

- Only this plan's files change: `server/sources/claude.mjs`, `server/sources/claude.test.mjs`, `fixtures/claude/**`; plan 1's files and `package.json` are frozen, so no new npm dependency — Node built-ins only (`node:fs`, `node:path`, `node:os`, `node:test`, `node:assert`) (user; verified: roadmap ownership table).
- The relay discovers `server/sources/*.mjs` by directory read, skips names ending in `.test.mjs`, and calls `start({emit, sendCommand})` with no flags; it parses its own argv with `parseArgs({strict:false, allowPositionals:true})` and ignores flags it does not own, so `--claude-*` flags pass through to the source, which reads `process.argv` and env itself; the test therefore stays beside the module at `server/sources/claude.test.mjs` (verified: plan 1 Task 1 as amended 2026-10-17; plan 1 End state 9).
- Every emitted frame is one of plan 1's protocol shapes and passes `isServerEvent`; `parent`, `phase`, `args`, `summary`, `diff`, and `ts` are optional, and a frame omits an absent field rather than carrying `undefined`; the client never sees a harness-specific field (verified: plan 1 Task 1 as amended 2026-10-17; PIN-19).
- The relay caches the last `session` and `state` frame per sid plus the last 200 slabs and replays `mode`, `session`, `state`, and slab frames to every late-joining client, so this source emits each `session` once at first track and `state` only on change (verified: plan 1 Task 1 as amended 2026-10-17).
- Claude Code obelisks are read-only targets: a source without `sendCommand` is read-only, so the module exports neither `sendCommand` nor `handle`, and plan 2's `say`, `fork`, `pipe` answer `read-only harness` for them; the optional contract exports `titleOf(sid)` and `slabText(sid, id)` are still provided, so a pipe FROM a Claude obelisk reads its real title (user; verified: plan 1 D6 and Task 1).
- One worker, one task, at most 90 minutes inside the window from 3 PM to 5:15 PM; the Quest slot from 5:30 PM to 6:30 PM is the only headset time after this plan lands (user).
- The demo is shared by QR code to anyone at the venue and the repo is a hackathon submission, so fixtures carry placeholder text only — no real transcript content, paths, or titles (user: present a QR code so anyone can hop in).

## Non-goals / deferred

Writing into Claude Code sessions (`say`, `fork`, `pipe` targets) · hook-based push ingestion · `delta` streaming (a transcript line is a whole block; there is no partial text to stream) · live retitling after a `custom-title` line arrives mid-session · rendering `attachment`, `file-history-*`, or `tool-results/` content · reading `journal.jsonl` for anything beyond fixture fidelity · Hermes, pylons, voice, gestures, and state beacons (plans 2, 4, 5, 6).

## Commander's Intent

- **Purpose:** every Claude Code session active on the laptop, and every subagent it spawns, stands in the room as an obelisk the moment its transcript changes, with no change to the client or the relay.

## Notes / conscious deviations

- The fixture tree nests under `fixtures/claude/demo-project/main/…` rather than the flat `fixtures/claude/main.jsonl` + `fixtures/claude/subagents/…` the task text lists, so `--claude-root fixtures/claude` exercises the real `<root>/<slug>/<sid>` discovery and doubles as a demo fallback; an explicit `--claude-root` exempts the recency window, so the fallback shows the fixture room regardless of the checkout's mtimes and needs no second flag. Every named file is present, one level deeper. Ownership is unchanged: the roadmap grants `fixtures/claude/**`.
- The fixture's assistant turn is three lines sharing `message.id` (thinking, tool_use, text), as the live transcript writes it, instead of one line with several blocks; `mapLine` handles any number of blocks per line either way.
- `file-history-delta` and `system` join the skip list because they appear in today's transcript; `summary` stays on the list from the task text although no current transcript here contains it.
- A recency window (`--claude-since`), a session cap (`--claude-max`), and a per-parent agent cap (`--claude-max-agents`) are added beyond plan 1's D20 wording because the root holds 336 transcripts; without them the room would show hundreds of obelisks. At the demo, pass `--claude-max 3` on the relay command line so three chats and their agents stay near plan 1 A7's six-obelisk budget.
- Tool calls emit a role `tool` slab beside the `tool` frame so the obelisk shows the call in its stack and plan 4 has a slab mesh (`userData.slabId` = the tool id) to launch a projectile from; plan 1's protocol already allows role `tool` slabs.
- `custom-title.json` sits in the fixture so the integration test covers the sidecar path; End state 5 covers the `custom-title` line branch by removing the sidecar and restarting, and the first-user-text branch through the pure `deriveTitle` pin.
- `titleOf(sid)` and `slabText(sid, id)` are exported although the source is read-only: plan 1 names them as optional source exports and plan 2's `pipe` resolves the FROM title through `ownerOf(from).titleOf`, so a pipe out of a Claude obelisk carries its real title; the pure precedence helper is named `deriveTitle` to keep the contract name free.
- The test stays at `server/sources/claude.test.mjs`: plan 1's loaders skip names ending in `.test.mjs`.
- The test-backed End states are numbered 1 to 9 so `--test-name-pattern='^ES<n>'` matches exactly one case (`^ES1` also matches a case named `ES12`); every such check passes `--test-reporter=tap` because Node 24 defaults to the `spec` reporter even when piped and prints `ℹ pass`, not `# pass` (verified on this laptop's Node v24.17.0, 2026-10-17).
